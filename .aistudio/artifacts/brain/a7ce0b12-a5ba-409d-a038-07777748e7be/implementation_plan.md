# Унификация адаптивного макета (1280px), дизайн-токенов и типографики

Комплексный план перехода интерфейса на единый адаптивный контейнер с шириной 1280px, устранение сжатого 700px-макета, внедрение дизайн-токенов (отступы 4/8/12/16/24/32px, радиусы, цвета статусов, типографика $\ge 12$px), унификация крупных числовых метрик и приведение контраста вторичного текста к стандарту WCAG AA.

---

## User Review & Critical Decisions

> [!IMPORTANT]
> На основе ответов в интерактивном интервью зафиксированы следующие параметры сетки:
> - **Главная страница (Обзор / Дашборд)**: на экранах $\ge 1280\text{px}$ формируется 3-колоночная сетка: ключевые метрики капитала и баланса слева, интерактивный график тренда по центру, недавние финансовые операции справа.
> - **Счета и банковские продукты**: на десктопе ($\ge 1280\text{px}$) карточки банков располагаются в адаптивной 2-колоночной сетке равной ширины с сохранением структуры продуктов (карты, вклады, накопительные счета).
> - **Сохранение данных и логики**: данные, расчеты капитала, операции, цели и фильтрация остаются нетронутыми — изменения затрагивают только контейнеры, сетки, токены и общие UI-компоненты.

---

## 1. Overview & Core Concept

- **Проблема**: На экранах ноутбуков и мониторов (1440px, 1920px) контент приложения был зажат в узкую колонку шириной около 700px (`max-w-2xl` / `max-w-md`), из-за чего страницы выглядели пустыми с широкими неиспользуемыми полями. Одновременно в коде присутствовали разрозненные значения отступов, радиусов скруглений, мелкий текст менее 12px и контраст серого цвета ниже порога читаемости.
- **Целевое решение**:
  1. **Единый центрированный контейнер**: `max-w-[1280px] w-full mx-auto px-4 sm:px-6 lg:px-8` с `overflow-x-hidden` для гарантированного отсутствия горизонтальной полосы прокрутки.
  2. **Адаптивная сетка**:
     - $\ge 1280\text{px}$ (десктоп): 2–3 колонки в зависимости от смысловой нагрузки раздела.
     - $768\text{px} - 1279\text{px}$ (планшет): 2 колонки.
     - $< 768\text{px}$ (мобильные): 1 колонка с сохранением сенсорной эргономики.
  3. **Централизованные дизайн-токены** в `src/designTokens.ts`: строгая шкала отступов (4/8/12/16/24/32px), радиусов, цвета статусов (доход, расход, предупреждение) и типографики.
  4. **Единый стиль крупных чисел**: унифицированный класс шрифта (`font-mono tracking-tight font-bold`) для метрик одного иерархического уровня.
  5. **WCAG AA контрастность**: повышение читаемости вторичного текста (замена тусклого `text-neutral-600` на контрастный `text-neutral-400` / `text-neutral-300`, коэффициент контрастности $\ge 4.5:1$ на темном фоне).

### 2.2 Шкала токенов (`src/designTokens.ts`)
- **Отступы (Spacing Scale)**:
  - `xs`: `4px` (`gap-1`, `p-1`)
  - `sm`: `8px` (`gap-2`, `p-2`)
  - `md`: `12px` (`gap-3`, `p-3`)
  - `lg`: `16px` (`gap-4`, `p-4`)
  - `xl`: `24px` (`gap-6`, `p-6`)
  - `2xl`: `32px` (`gap-8`, `p-8`)
- **Радиусы (Border Radii)**:
  - `md`: `rounded-lg` (8px) — кнопки, бейджи, инпуты
  - `lg`: `rounded-xl` (12px) — вложенные плашки, компактные карточки
  - `xl`: `rounded-2xl` (16px) — внешние контейнеры карточек
- **Типографика**:
  - Первичный заголовок / крупное число (Level 1 KPI): `text-2xl sm:text-3xl font-bold font-mono tracking-tight text-white`
  - Вторичное число (Level 2 Sub-KPI): `text-lg sm:text-xl font-bold font-mono text-neutral-100`
  - Строчный ценник / транзакция (Level 3 Item): `text-sm font-semibold font-mono`
  - Базовый текст: `text-sm text-neutral-200`
  - Вторичный поясняющий текст (Secondary Label): `text-xs text-neutral-400` (минимум 12px, строгий запрет на нечитаемый 10px-серый)
- **Цвета статусов**:
  - `income`: текст `text-emerald-400`, фон `bg-emerald-500/10`, обводка `border-emerald-500/30`
  - `expense`: текст `text-rose-400` / `text-red-400`, фон `bg-rose-500/10`, обводка `border-rose-500/30`
  - `warning`: текст `text-amber-400`, фон `bg-amber-500/10`, обводка `border-amber-500/30`
  - `neutral`: текст `text-neutral-300`, фон `bg-[#161b22]`, обводка `border-[#30363d]`

## 3. Key Product Decisions & Trade-Offs

- **Решение 1: Модуль `designTokens.ts` с готовыми классами Tailwind**:
  - *Выбор*: Экспортировать готовые семантические наборы классов (`tokens.card.base`, `tokens.badge.income`, `tokens.number.kpiPrimary`, `tokens.typography.secondary`) вместо сырых CSS-переменных.
  - *Почему*: Обеспечивает строгую консистентность по всему коду без нарушения сборки Tailwind и ускоряет рендеринг.
- **Решение 2: Адаптивный грид без горизонтального скролла**:
  - *Выбор*: Все таблицы и широкие списки оборачиваются в адаптивные флекс/грид-блоки или `overflow-x-auto` внутри фиксированных контейнеров, а корневой макет снабжается `w-full overflow-x-hidden`.
  - *Почему*: На мобильных устройствах (390px) и планшетах (768px, 1024px) экран не будет смещаться влево-вправо.
- **Решение 3: Локализация применения токенов**:
  - *Выбор*: Заменить разрозненные значения на токены в общих компонентах (карточка `Card`, кнопка `Button`, бейдж `Badge`, заголовок `CardHeader`, строки сумм).
  - *Почему*: Точно следует требованию пользователя: не трогать логику и структуру данных, только контейнер, сетку, токены и общие компоненты.

### 4.2 План верификации по ширинам экранов:
- **1920px (Full HD Десктоп)**: контент центрирован с комфортными отступами по бокам (`max-w-[1280px] mx-auto`), нет ощущения пустых растянутых полей; 3 колонки в дашборде, 2 колонки банковских продуктов.
- **1440px (Стандартный ноутбук / монитор)**: ровная сетка с отступами `px-6`–`px-8`, плотное информативное наполнение.
- **1024px (Планшет ландшафт / компактный ноутбук)**: 2 колонки, плавный переход без разрывов строк.
- **768px (Планшет портрет)**: 2 колонки для карточек банков, 1 колонка для тяжелых графиков.
- **390px (Мобильный iPhone / Android)**: 1 колонка, горизонтальный скролл отсутствует, сенсорные элементы $\ge 40$px, вторичный текст четко читаем ($\ge 12$px, WCAG AA $\ge 4.5:1$).
- **Компиляция**: Запуск `compile_applet` и `lint_applet` для подтверждения целостности сборки без ошибок TypeScript.
